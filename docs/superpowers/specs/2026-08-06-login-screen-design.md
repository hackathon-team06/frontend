# 로그인 화면 설계

**작성일:** 2026-08-06
**대상:** Stay:Care 프론트엔드 — 로그인 화면
**Figma:** [중앙해커톤 파일, node-id 449-2095](https://www.figma.com/design/ePT8aZw07S36LCpkxqb1Md/%EC%A4%91%EC%95%99%ED%97%A4%EC%BB%A4%ED%86%A4?node-id=449-2095&m=dev)

## 개요

앱 진입 경로 `/`에 로그인 화면을 만든다. 아이디와 비밀번호를 입력받아 프론트엔드에 고정한 테스트 계정과 대조하고, 일치하면 `/home`으로 이동한다.

## 배경과 제약

- 백엔드 로그인 API가 아직 없다. 인증은 프론트엔드에 상수로 둔 테스트 계정 하나와의 문자열 대조로 처리한다. 백엔드에서 계정을 전달받으면 상수 값만 교체한다.
- 이 방식은 보안 경계가 아니다. 아이디와 비밀번호가 번들에 그대로 들어가고 판정도 브라우저에서 난다. 데모 흐름을 위한 장치로만 취급한다.
- `App.jsx`에 새 라우트를 추가하지 않는다. 로그인 화면은 기존 `/` 경로에 놓고, 비어 있던 `Main.jsx`를 채우는 방식으로 만든다. `/`가 가리키는 컴포넌트가 `Home`에서 `Main`으로 바뀌는 것은 이 설계가 요구하는 변경이며, 그 외에 라우트를 추가·삭제·재배치하지 않는다.
- 언어는 JavaScript(JSX), 스타일은 Tailwind CSS. 프로젝트에 TypeScript가 설치돼 있지 않고 기존 페이지 전부가 `.jsx`이므로 기존 컨벤션을 따른다.

## 선행 문제: 작업 트리의 빌드 실패

작성 시점의 작업 트리에서 `npm run build`가 실패했다.

```
import Main from "./pages/Main";
                 ─────┬─────
                      ╰── Module not found.
```

커밋된 상태(`b82c3d3`)는 정상이었다. `/`가 `Home`을 가리키고 `Main` import 자체가 없었다. 실패는 개발자가 로그인 라우트를 붙이려고 손대던 **커밋 전 변경**에서 나왔다. `./pages/Main`을 가리키는데 실제 파일은 `src/pages/Main/Main.jsx`이고 `index.jsx`가 없어서 해석되지 않았다. 다른 페이지들은 `./pages/Home/Home` 형태로 올바르게 작성돼 있다.

이 작업의 대상 파일이므로 함께 정리한다. import 경로를 고치고, `/` → `Main` 변경을 같은 커밋에 담는다.

## 범위

**포함**

- 로그인 화면 UI (Figma 시안 기준)
- 아이디·비밀번호 입력과 제출 처리
- 테스트 계정 대조 및 성공 시 `/home` 이동
- 실패 시 에러 메시지 표시
- 로그인 상태를 zustand 스토어에 보관
- 로그인 화면에서 하단 Footer 숨김
- `App.jsx`의 잘못된 import 경로 수정

**제외**

- 회원가입, 비밀번호 찾기, 소셜 로그인
- 로그인 상태의 `localStorage` 영속화
- 로그인 여부에 따른 라우트 보호
- 로그아웃 기능
- 백엔드 API 연동

제외 항목의 확장 방법은 문서 마지막의 "향후 확장"에 적는다.

## 파일 구성

### 새로 만드는 파일

| 파일 | 책임 |
| :--- | :--- |
| `src/store/authStore.js` | zustand 스토어. 로그인 여부와 로그인한 아이디 보관 |
| `src/constants/auth.js` | 테스트 계정 상수 |
| `src/assets/images/login_visual.png` | 상단 장식 영역 이미지 |

`src/pages/Main/Main.jsx`는 이미 존재하는 빈 컴포넌트이며, 로그인 화면 내용으로 채운다.

### 수정하는 파일

| 파일 | 변경 |
| :--- | :--- |
| `src/App.jsx` | 2번째 줄 import 경로를 `"./pages/Main/Main"`으로 수정 |
| `src/layout/RootLayout.jsx` | Footer 표시 조건 변경 (아래 "Footer 처리" 참고) |

### `constants/auth.js`를 분리하는 이유

백엔드에서 계정을 전달받았을 때 교체할 지점이 어디인지 한눈에 보이게 하기 위해서다. 스토어 안에 두면 나중에 찾기 어렵다.

```js
// 백엔드에서 테스트 계정을 전달받으면 아래 값을 교체한다.
export const TEST_ACCOUNT = {
  id: "test",
  password: "1234",
};
```

`id`, `password` 두 값은 백엔드 전달 전까지 사용할 임시 값이다.

### 컴포넌트 경계

`Main.jsx` 안에 입력 필드용 로컬 컴포넌트를 하나 정의한다. 아이디와 비밀번호가 같은 모양(360×60, 라운드, 연한 테두리)이므로 한 번만 정의하면 된다. `Register.jsx`가 `OptionButton`을 파일 내부에 두는 것과 같은 방식이다.

로그인 버튼은 기존 `components/common/MissionButton`과 크기·모양이 달라(144×40 대 360×60) 재사용하지 않고 `Main.jsx` 안에서 직접 작성한다.

## 화면 구성

Figma 프레임은 390×844이고 요소 배치는 다음과 같다. 좌표는 프레임 기준이다.

**상단 장식 영역 (y 0~550)**

민트 그라데이션 배경, `stay care` 로고, 태그라인 "집에서 시작하는 작은 변화"(y205), 말풍선 "매일 1분, / 나를 위한 작은 케어로 / 더 건강한 일상을 시작해요!"(x17 y274, 228×72 + 꼬리), 우측에서 프레임 밖으로 잘리는 3D 마스코트, 반짝임 장식 4개. 인터랙션은 없다.

**폼 영역**

| 요소 | 위치 | 크기 |
| :--- | :--- | :--- |
| 아이디 입력 | x15, y560 | 360×60 |
| 비밀번호 입력 | x15, y631 | 360×60 |
| 로그인하기 버튼 | x15, y702 | 360×60 |

버튼은 민트 배경에 흰 텍스트, 입력 필드는 흰 배경에 연한 테두리와 라운드 처리.

색상값·테두리 두께·모서리 반경·폰트 크기와 두께는 구현 시작 시 Figma MCP의 `get_design_context`로 해당 노드(아이디 `449:2111`, 비밀번호 `449:2113`, 버튼 `449:2115`)에서 추출해 Tailwind 임의값으로 옮긴다. 기존 페이지들이 쓰는 민트색은 `#65DBBE`이며, 시안 값이 이와 다르면 시안을 따른다.

## 상단 장식 영역 구현

장식 요소 전체를 이미지 한 장으로 처리한다. 마스코트가 3D 렌더라 벡터로 만들 수 없고, 그라데이션 배경도 SVG로 옮기면 무거워진다. 장식에 인터랙션이 없으므로 요소별로 나눌 이유가 없다.

Figma 시안에서 장식 요소들이 그룹으로 묶여 있지 않아 "상단만" 선택해 내보낼 수 없다. 따라서 **프레임 `449:2095` 전체를 2배 해상도(780×1688) PNG로 export해 `src/assets/images/login_visual.png`로 저장한 뒤, `overflow-hidden` 컨테이너로 상단 550px만 노출하고 나머지는 CSS로 잘라낸다.**

550px은 첫 입력 필드가 시작하는 y560 바로 위 지점이다.

```jsx
<div className="w-[390px] h-[550px] overflow-hidden">
  <img src={loginVisual} className="w-[390px]" />
</div>
```

클립 경계에서 배경색이 어긋나 이음새가 보이면 클립 높이를 조정한다. 이미지 하단부가 사용되지 않지만 파일 크기 증가는 무시할 수준이다.

내보낸 PNG에는 시안의 iPhone 상태바가 포함된다. 다른 페이지들이 `phone.svg`를 따로 렌더하는 것과 결과가 같으므로 이 화면에서는 `phone.svg`를 사용하지 않는다.

## 동작 흐름

`Main.jsx`가 아이디와 비밀번호를 각각 `useState`로 보관하는 제어 컴포넌트 방식이다.

폼 전체를 `<form>`으로 감싸고 로그인 버튼을 `type="submit"`으로 둔다. 버튼 클릭과 Enter 키가 같은 경로를 타므로 처리 분기가 하나로 유지되고, 모바일 키보드의 "완료"에서도 동작한다. 비밀번호 입력은 `type="password"`로 마스킹한다.

제출 시 `TEST_ACCOUNT`와 대조한다.

- **일치** — `authStore`에 로그인 상태를 기록하고 `navigate("/home")`
- **불일치** — 에러 메시지를 표시하고 화면 유지

## 상태 관리

`src/store/authStore.js`에 zustand 스토어를 만든다. 보관하는 것은 세 가지다.

| 이름 | 설명 |
| :--- | :--- |
| `isLoggedIn` | 로그인 여부. 초기값 `false` |
| `userId` | 로그인한 아이디. 초기값 `null` |
| `login(userId)` | `isLoggedIn`을 `true`로, `userId`를 인자값으로 설정 |

`logout()`은 이번 범위에서 호출하는 곳이 없으므로 만들지 않는다.

상태는 메모리에만 남는다. 새로고침하면 초기화되며, 이는 의도된 동작이다. 영속화하지 않기로 한 이유와 확장 방법은 "향후 확장"에 적는다.

## Footer 처리

`RootLayout.jsx`가 `pathname !== "/register"`일 때만 Footer를 숨기고 있어, 그대로 두면 로그인 화면에도 하단 탭바가 표시된다. 시안에는 없다.

숨길 경로를 배열로 관리한다.

```jsx
const HIDE_FOOTER = ["/", "/register"];
...
{!HIDE_FOOTER.includes(pathname) && <Footer />}
```

조건을 `&&`로 이어붙이는 것보다, 온보딩·회원가입 화면이 추가될 때 목록에 한 줄 넣는 편이 낫다. `Route` 구성은 변경하지 않으며 Footer 표시 여부만 바뀐다.

`RootLayout`의 `main`에 걸린 `pb-20`(80px)은 Footer 자리 확보용이지만 Footer를 숨겨도 남는다. 시안에서 로그인 버튼이 y762에서 끝나고 프레임이 844이므로 하단 여백이 82px이고, `pb-20`과 거의 일치한다. 따라서 그대로 둔다.

## 에러 처리

시안에 에러 영역이 없어 위치를 정해야 한다. 비밀번호 필드와 버튼 사이는 11px뿐이라 메시지를 넣으면 버튼이 밀려 레이아웃이 깨진다. **버튼 아래 여백(82px)에 표시한다.** 이 위치는 어떤 요소도 밀지 않는다.

문구는 `아이디 또는 비밀번호가 일치하지 않습니다.` 하나만 사용한다. 빈 값으로 제출한 경우에도 같은 메시지를 표시한다. 아이디와 비밀번호 중 무엇이 틀렸는지 구분해 알리는 것은 실제 인증에서 피해야 할 관행이고, 여기서도 사용자가 얻는 것이 없다.

버튼 비활성화 상태는 시안에 없으므로 만들지 않는다. 입력이 비어 있어도 제출은 가능하고, 위 메시지가 표시된다.

에러 메시지는 다음 제출 시 초기화된다.

## 검증

프로젝트에 테스트 프레임워크가 설치돼 있지 않고, 해커톤 일정에 새로 도입하는 것은 비용에 비해 얻는 것이 적다. 다음으로 확인한다.

1. **`npm run build` 통과** — 현재 실패하는 빌드가 복구됐는지 확인하는 것이 첫 관문이다
2. **`npm run lint` 통과**
3. **수동 확인**
   - `/`가 시안대로 렌더되고 하단 Footer가 보이지 않는다
   - 비밀번호 입력이 마스킹된다
   - 틀린 계정으로 제출하면 버튼 아래에 에러 메시지가 표시되고 화면이 유지된다
   - 빈 값으로 제출해도 같은 메시지가 표시된다
   - 맞는 계정으로 제출하면 `/home`으로 이동하고 Footer가 다시 보인다
   - Enter 키로도 제출된다

## 향후 확장

이번 범위에서 제외한 항목들의 확장 경로다.

**로그인 상태 유지** — zustand의 `persist` 미들웨어로 `authStore` 선언을 감싸면 `localStorage`에 저장된다. 컴포넌트 코드는 바뀌지 않는다. 이어서 `Main.jsx` 진입 시 `isLoggedIn`을 확인해 `/home`으로 넘기면, 앱처럼 "이미 로그인된 상태면 로그인 화면을 건너뛰는" 흐름이 된다. 이 판단이 로그인 페이지 자신의 책임 안에 머무르므로 다른 파일을 건드리지 않는다.

이번에 넣지 않은 이유는, 상태가 유지되면 로그인 화면을 다시 보려면 로그아웃 수단이 필요해지고 그만큼 범위가 커지기 때문이다. 새로고침이 곧 초기화인 지금은 별도 장치가 필요 없다.

**라우트 보호** — 백엔드 인증이 붙어 실제 보안 경계가 생기는 시점에 추가한다. 지금은 테스트 계정이 번들에 노출돼 있어 가드를 씌워도 막는 대상이 URL을 직접 입력한 사용자뿐이다.

**로그아웃** — `authStore`에 `logout()`을 추가하고 마이페이지에서 호출한다.

**백엔드 연동** — `constants/auth.js` 대조를 `api/` 하위의 axios 호출로 교체한다. `Main.jsx`의 제출 처리를 비동기로 바꾸고 로딩·실패 상태를 다루게 된다. `authStore`에는 토큰 보관이 추가된다.
