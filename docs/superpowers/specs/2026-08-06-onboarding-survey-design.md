# 온보딩 진단 설문 설계

**작성일:** 2026-08-06
**대상:** Stay:Care 프론트엔드 — 로그인 직후 진행하는 온보딩 진단 설문
**Figma:** [설문 플로우 파일, node-id 1-3](https://www.figma.com/design/aoS5iGGARfUmDknJfwopdT/%EC%A0%9C%EB%AA%A9-%EC%97%86%EC%9D%8C?node-id=1-3&m=dev)
**작업 브랜치:** `feat/#10-questions-ui` (base: `develop` @ `40bc5f8`)

## 개요

로그인에 성공한 사용자에게 6개 문항의 진단 설문을 보여주고, 답변을 `localStorage`에 저장한 뒤 `/home`으로 보낸다. 설문은 사용자당 최초 1회만 진행하며, 이미 마친 사용자는 로그인 후 곧바로 `/home`으로 간다.

## 배경과 제약

- 백엔드가 없다. 답변은 전송하지 않고 `localStorage`에만 저장한다.
- 로그인 상태는 메모리에만 존재한다(로그인 작업에서 결정). 새로고침하면 로그아웃된다. 이 설계는 그 결정을 바꾸지 않는다.
- 언어는 JavaScript(JSX), 스타일은 Tailwind CSS. 기존 페이지 전부가 `.jsx`이므로 컨벤션을 따른다.
- 화면은 390px 폭 모바일 프레임 안에서 렌더된다.
- 문항이 나중에 늘어날 수 있다(예: 평균 귀가 시간). 문항 추가가 배열 한 줄 수정으로 끝나야 한다.

## 범위

**포함**

- 문항 6개 화면과 로딩 화면
- 단일 선택, 필수 응답, 미선택 시 하단 버튼 비활성
- 뒤로가기(이전 문항으로, 선택값 유지)
- 진행 바
- 답변과 완료 여부를 `localStorage`에 저장
- 로그인 성공 시 완료 여부에 따라 `/onboarding` 또는 `/home`으로 분기
- 설문 화면에서 하단 탭바 숨김

**제외**

- 답변의 백엔드 전송
- 설문 도중 이탈 후 이어하기
- 로그인 상태 영속화
- 설문 재응시 기능
- 답변을 홈 화면 등 다른 화면에서 활용하는 것

제외 항목의 확장 경로는 문서 마지막에 적는다.

## 라우팅

`/onboarding` 라우트 하나만 추가하고, 단계는 컴포넌트 내부 상태로 관리한다. 문항마다 라우트를 두거나 `/onboarding/:step` 파라미터를 쓰지 않는다.

문항별 라우트는 브라우저 뒤로가기와 딥링크를 얻지만, 이 앱에서 둘 다 쓰이지 않는다. 시안이 화면 안에 뒤로가기 화살표를 그려둔 것 자체가 브라우저 버튼을 상정하지 않는다는 뜻이다. 반면 대가는 실재한다. 라우트가 7개 늘고, `HIDE_FOOTER`가 정확한 경로 비교라 접두어 매칭으로 바꿔야 하며, 앞 문항을 건너뛰고 진입하는 경우를 막는 가드가 화면마다 필요하다.

흐름이 완전히 선형이고 외부에서 특정 단계로 진입할 일이 없으므로, 단계는 URL이 아니라 컴포넌트가 갖는다.

**브라우저 뒤로가기의 결과** — 설문 도중 브라우저 뒤로가기를 누르면 이전 문항이 아니라 로그인 화면으로 나간다. 의도된 동작이다.

### 문항 데이터 구조

`onboardingQuestions.js`는 문항 배열 하나를 내보낸다. 각 항목은 식별자, 제목, 렌더러 유형, 선택지 목록을 갖는다. 목록형은 행 높이가 문항마다 달라(68px / 56px) 항목에 명시한다. 상세형 선택지는 태그와 설명 3줄을, 그리드형 선택지는 아이콘을 추가로 갖는다.

문항을 추가하려면 이 배열에 항목을 하나 넣는다. 컴포넌트는 건드리지 않는다.

## 데이터 흐름

`Onboarding.jsx`가 현재 단계와 답변을 **로컬 상태로** 들고 있다가, 마지막 문항에서 하단 버튼을 누르는 순간 스토어에 **한 번만** 기록하고 로딩 화면으로 넘어간다. 선택할 때마다 `localStorage`에 쓰지 않는다.

단계는 0부터 문항 개수까지의 정수다. 문항 개수와 같아지면 `Onboarding.jsx`가 문항 화면 대신 로딩 화면을 렌더한다. 로딩 화면은 별도 라우트가 아니라 같은 `/onboarding` 안의 마지막 단계다.

로그인 상태가 메모리에만 있어 설문 도중 새로고침하면 로그아웃된다. 재로그인 후 저장된 단계부터 이어가게 만들 수는 있지만, 그러려면 저장된 단계가 문항 개수 범위 안인지 검증해야 하고 완료 시 진행 상태를 비울지 정해야 한다. 문항이 나중에 추가될 예정이므로 이 검증은 실제로 어긋날 수 있는 지점이다 — 5번에서 멈춘 사용자가 문항 추가 후 재방문하면 엉뚱한 문항으로 간다. 6문항짜리 설문에서 되찾는 것은 30초이므로 넣지 않는다.

결과적으로 스토어는 "진행 중 스크래치패드"가 아니라 **"완료된 설문 결과"** 하나만 뜻한다.

### 스토어

`src/store/onboardingStore.js`에 zustand 스토어를 만들고 `persist` 미들웨어로 감싼다.

| 이름 | 설명 |
| :--- | :--- |
| `answers` | 문항 식별자를 키로, **선택한 선택지의 식별자**를 값으로 갖는 객체. 화면에 보이는 라벨이 아니라 식별자를 저장한다 — 라벨 문구가 바뀌어도 저장된 답이 깨지지 않고, 나중에 백엔드로 보낼 때도 식별자가 맞다. 초기값 `{}` |
| `hasCompletedOnboarding` | 완료 여부. 초기값 `false` |
| `completeOnboarding(answers)` | `answers`를 인자값으로 설정하고 `hasCompletedOnboarding`을 `true`로 |

`resetOnboarding()`은 호출하는 곳이 없으므로 만들지 않는다.

### 로그인 후 분기

`Main.jsx`의 로그인 성공 처리가 현재 `navigate("/home")` 한 줄이다. 여기서 `hasCompletedOnboarding`을 확인해 `false`면 `/onboarding`으로, `true`면 `/home`으로 보낸다. 판단이 로그인 화면 자신의 책임 안에 머무르므로 다른 파일은 건드리지 않는다.

### 로그아웃 상태 진입 차단

설문 도중 새로고침하면 로그아웃 상태로 `/onboarding` 화면만 남는다. 화면은 정상 렌더되지만 그대로 끝까지 진행하면 로그아웃 상태인데 설문은 완료된 앞뒤 안 맞는 상태가 된다.

`Onboarding.jsx` 진입 시 `isLoggedIn`을 확인해 `false`면 `/`로 되돌린다. 모든 페이지에 씌우는 라우트 가드가 아니라 이 화면 하나가 자기 전제를 확인하는 것이다.

## 화면 동작

**진행 바** — 문항 개수만큼 칸을 균등 분할해 현재 단계까지 채운다. 시안은 356px 안에 56px짜리 6칸이지만 이 수치를 고정하지 않는다. 문항이 7개가 되면 바가 넘치기 때문이다. flex로 균등 분할하면 6개일 때 시안과 같은 56px가 나오고, 개수가 바뀌어도 폭이 맞는다. 로딩 화면에는 진행 바가 없다.

**뒤로가기** — 1번 문항에는 화살표가 없다. 2~6번에서 누르면 이전 문항으로 가고, 그때 선택했던 답이 선택된 채로 남는다. 로딩 화면에서는 되돌아갈 수 없다.

**선택** — 모든 문항이 단일 선택이다. 이미 고른 상태에서 다른 선택지를 누르면 교체된다.

**하단 버튼** — 답을 고르기 전에는 비활성이다. 시안에 비활성 상태가 따로 그려져 있지 않으므로 투명도를 낮춰 처리한다. 버튼 문구는 시안 컴포넌트 내부에 있어 메타데이터로 확인되지 않았다. 구현 시작 시 `get_design_context`로 노드 `1:1893`(1번 문항의 버튼 인스턴스)에서 문구와 색상을 확인해 반영한다.

**로딩 화면** — 2초 뒤 `/home`으로 이동하되 히스토리를 교체한다(`navigate("/home", { replace: true })`). 그래야 홈에서 브라우저 뒤로가기를 눌렀을 때 로딩 화면으로 돌아오지 않는다. 화면을 벗어나면 타이머를 정리한다.

## 에셋

로그인 화면은 상단 장식 전체를 PNG 한 장으로 처리했지만, 이 화면들은 선택지 하나하나가 눌리는 요소이므로 개별로 내려받는다.

대상과 해당 노드는 다음과 같다. 구현 시작 시 `download_assets`로 내려받는다.

| 에셋 | 노드 | 크기 |
| :--- | :--- | :--- |
| 마스코트 (문항 화면 상단) | `1:1911`, `1:2056` | 92×82 |
| 뒤로가기 화살표 | `1:1944` | 21×42 |
| 계기 카드 아이콘 6개 | `1:2167` `1:2171` `1:2174` `1:2177` `1:2180` `1:2183` | 28~41 |
| 로딩 화면 아이콘 | `1:2227`~`1:2233` | 32~124 |

마스코트는 1번 문항이 `image 47`, 3번 문항부터는 `집착이`라는 다른 이름의 인스턴스다. 같은 그림인지 다른 포즈인지 확인해 필요한 만큼만 받는다.

**라디오 버튼(18×18)은 에셋 대신 CSS로 그린다.** 선택·미선택 두 상태를 이미지 두 장으로 관리하는 것보다 클래스 토글이 간단하고, 색상 변경도 쉽다.

## 검증

프로젝트에 테스트 프레임워크가 없고 도입하지 않기로 했다(로그인 작업에서 결정). 다음으로 확인한다.

1. **`npm run build` 통과**
2. **`npm run lint` 통과**
3. **수동 확인**
   - 로그인하면 설문 1번 문항이 뜨고, 하단 탭바가 보이지 않는다
   - 답을 고르기 전 하단 버튼이 비활성이고, 고르면 활성된다
   - 6개 문항을 끝까지 진행하면 로딩 화면이 2초 뜬 뒤 `/home`으로 가고 탭바가 복귀한다
   - 뒤로가기로 이전 문항에 가면 선택했던 답이 남아 있다
   - 1번 문항에는 뒤로가기 화살표가 없다
   - 피부 타입 화면이 세로로 스크롤된다
   - `/home`에서 브라우저 뒤로가기를 눌러도 로딩 화면으로 돌아오지 않는다
   - 완료 후 새로고침하고 다시 로그인하면 설문을 건너뛰고 바로 `/home`으로 간다
   - `localStorage`에 답변 6개와 완료 플래그가 남아 있다

## 향후 확장

**문항 추가** — `onboardingQuestions.js` 배열에 항목을 추가한다. 목록형 문항이면 컴포넌트 변경이 전혀 없다. 진행 바는 개수를 따라간다.

단 **선택지 개수에 상한이 있다.** 하단 버튼이 844px 프레임 안 `top: 750`에 고정돼 있고 선택지는 `top: 283`에서 시작하므로, 행 높이 68px + 간격 11px 기준으로 **5개까지** 들어간다 (5개 = 667px에서 끝나 여유 83px). 6개면 746px까지 내려와 버튼에 닿고, 7개면 겹친다. 선택지가 6개 이상인 문항을 추가할 때는 피부 타입 문항처럼 같은 항목에 `height`와 `buttonTop`을 함께 지정해야 한다 — 여전히 배열 항목 하나지만, 필드가 두 개 더 붙는다.

**답변의 백엔드 전송** — 로딩 화면의 2초 타이머 자리에 API 호출을 넣는다. 화면이 이미 "정보를 확인하고 있습니다"라는 대기 상태이므로 구조를 바꿀 필요가 없다. 실패 처리(재시도 또는 오류 안내)가 이때 추가된다.

**설문 도중 이어하기** — 스토어에 현재 단계와 진행 중 답변을 추가하고 `Onboarding.jsx`가 저장된 값에서 시작하게 한다. 저장된 단계가 문항 개수 범위 안인지 확인하는 처리가 함께 필요하다.

**로그인 상태 유지** — `authStore` 선언을 `persist`로 감싼다. 컴포넌트 코드는 바뀌지 않는다. 다만 로그인 화면과 설문을 다시 보려면 로그아웃 수단이 필요해지므로, 마이페이지의 로그아웃 버튼과 함께 진행하는 것이 맞다.

**답변 활용** — 홈 화면 등에서 `onboardingStore`의 `answers`를 읽는다. 스토어가 이미 영속화돼 있으므로 추가 작업이 없다.
